# Mindsphere

Каталог программ мероприятий DI EVENT и рабочий раздел сотрудников на Django.

## Возможности

- Посетители без регистрации просматривают публичный каталог из 21 программы. Компьютерная версия основана на макете PDF, мобильная использует адаптивную вертикальную вёрстку. Оглавление ведёт к программам на той же странице.
- Сотрудники после входа открывают отдельные карточки с полным внутренним описанием, создают, редактируют и удаляют программы, меняют пароль.
- Учётные записи создаёт администратор. Самостоятельной регистрации нет. Вход доступен по прямой ссылке `/auth/login/`; гостевой каталог её не показывает.

## Технологии

Python **3.12**, Django **6.1.3**, SQLite, Pillow, sorl-thumbnail, django-cleanup и pytils. Локальное окружение проверено на Python 3.12.12 / macOS.

Используется один `requirements.txt` с точными версиями. Комментарии разделяют пакеты приложения, инструменты разработки и транзитивные зависимости. Установка этого файла также устанавливает pytest, flake8, Debug Toolbar и django-extensions.

## Структура

```text
requirements.txt           # все зависимости
AGENTS.md                  # текущее состояние и правила работы с проектом
sphere/
    manage.py
    config/                # настройки и маршруты
    core/                  # общие вспомогательные компоненты
    events/                # модели, формы, каталог, импорт и тесты
    users/                 # вход и работа с учётными записями
    templates/             # HTML и SVG-шаблоны
    static/                # общая исходная статика
    db.sqlite3             # локальная база, не хранится в Git
    media/                 # загруженные файлы и миниатюры, не хранятся в Git
```

Стили, скрипты и ресурсы отдельных приложений находятся также в `sphere/events/static/` и `sphere/users/static/`.

## Установка и локальный запуск

Команды ниже выполняются из корня репозитория на macOS/Linux. Для новой установки нужен Python 3.12:

```bash
python3.12 -m venv venv
venv/bin/python -m pip install -r requirements.txt
venv/bin/python sphere/manage.py migrate
venv/bin/python sphere/manage.py createsuperuser
```

Если рабочее окружение `venv` уже существует, пересоздавать его не требуется. `migrate` создаёт или обновляет схему базы; программы каталога эта команда не загружает. Миграции приложения хранятся в репозитории, включая 0012 и 0013 с публичными полями и настройками публикации.

Запуск сервера разработки:

```bash
venv/bin/python sphere/manage.py runserver
```

| Адрес | Назначение |
| --- | --- |
| `http://127.0.0.1:8000/` | Публичный каталог |
| `http://127.0.0.1:8000/auth/login/` | Вход сотрудников |
| `http://127.0.0.1:8000/admin/` | Администрирование и создание пользователей |
| `/events/<slug>/` | Полная карточка, доступна после входа |
| `/create/` | Добавление программы, доступно после входа |

## Первоначальная загрузка каталога

В репозитории есть исходные данные всех 21 программы, иллюстрации, шрифты и SVG-макеты. Оригинальный PDF для запуска не требуется. Для заполнения новой базы выполните:

```bash
venv/bin/python sphere/manage.py load_pdf_catalog --replace
```

**Повторный запуск перезаписывает публичные поля исходных программ значениями из PDF**, включая тексты, порядок и ссылки на иллюстрации. Флаг `--replace` также снимает остальные программы с публикации. Пользователи, внутренние описания и прежние файлы сохраняются.

Используйте импорт для новой базы или намеренного восстановления исходного каталога. Для переноса уже отредактированного сайта нужны его база и медиафайлы. Импорт не вызывается автоматически при запуске или применении миграций.

## Редактирование и данные

Обе версии каталога используют одну модель `Event`. Название, слоган, краткое описание, состав концепции, формат, тайминг и дресс-код — публичные поля. Полное поле `description` предназначено только для сотрудников и может быть пустым. Оно не подставляется вместо краткого публичного описания.

Программы сортируются по `sort_order`, затем по ID. Флаг `is_published` управляет показом в каталоге. Обычные изменения выполняются через формы сайта или админку и сохраняются в базе. `sphere/events/catalog_source.json` — источник явного импорта, а не замена текущей базы. Поле `catalog_page` связывает исходную программу с её графическим макетом.

Тексты, пользователи и настройки программ хранятся в `sphere/db.sqlite3`, загруженные изображения — в `sphere/media/`. Эти данные исключены из Git. Копия репозитория сама по себе не переносит содержимое работающего сайта. Исходная статика, иллюстрации PDF и шрифты входят в репозиторий.

## Проверки

Из корня репозитория:

```bash
venv/bin/python -m pip check
venv/bin/python sphere/manage.py check
venv/bin/python sphere/manage.py makemigrations --check --dry-run
venv/bin/python sphere/manage.py showmigrations
venv/bin/python sphere/manage.py test events.tests users
```

Для общего набора Django-тестов и pytest-тестов после установки зависимостей:

```bash
cd sphere
../venv/bin/python -m pytest
```

Тесты используют отдельную тестовую базу. Проверка `makemigrations` выше не создаёт миграций и не применяет их к рабочей базе.

## Развёртывание

Текущие настройки предназначены для локальной разработки: `DEBUG=True`, `SECRET_KEY` задан в `settings.py`, `STATIC_ROOT` не настроен. Перед публикацией нужно вынести новый секретный ключ в окружение, настроить домен, HTTPS и обслуживание static/media при отключённом DEBUG. `runserver` предназначен для разработки.

Для Beget потребуется отдельная настройка серверного окружения Python 3.12 и способа запуска приложения. На существующем хостинге со старым сайтом на Python 3.9 совместимость нового окружения ещё не проверена. Локальный macOS-venv на сервер не переносится: зависимости устанавливаются в серверное окружение из `requirements.txt`.

При переносе текущего содержимого отдельно переносятся согласованная копия базы и каталог `media`. Если на сервере уже есть данные, сначала нужно сопоставить их с локальными, особенно пользователей и внутренние описания.
